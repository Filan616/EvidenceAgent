# 需求与验收边界

本项目服务于查询企业制度的员工。知识来源仅为本仓库七篇合成制度，不使用真实公司信息、个人资料或联网企业事实。输入是问题、可选 user/assistant 历史和制度适用日期；CLI 返回状态、受控答案、claims、citations、gaps、conflicts 和 trace_path。

## 必须满足

- Live 使用真实原生 Tool Calling；Python 不替模型选工具、改写查询或重试业务动作。
- 搜索与读取分离，只有本次成功读取的正文可引用；文档和历史不能改变系统权限。
- 事实声明核对 MAX/MIN/EXACT/DEADLINE、数值、单位、范围、周期、参考事件、必要条件和生效时间。
- COMPLETED 同时要求事实有效、无未消歧冲突，并覆盖全部核心问题。正确但不相关的规则不能完成回答。
- 冲突按规则组、范围、时间、约束互斥和显式覆盖关系判定；不能仅按版本新旧选制度。
- 模型错误、工具错误、无结果、预算耗尽分别记录。不得把 Mock、跳过测试或配置检查当作 Live 成功。

## 场景

| 场景 | 必要结果 |
|---|---|
| C01 正式员工额度 | 读取 D03，保留每周最多 2 天的上限语义 |
| C02 报销期限 | 读取 D01/D02，引用 30/15 天条款，请求确认 |
| C03 利润问题 | 成功检索后明确资料不足，不生成企业事实 |
| C04 相似表述 | 使用“正式员工在家上班”的改写问题，按实际路径记录是否改写检索 |
| C05 试用期追问 | 历史定位话题，重新读取 D04，不套用 D03 |
| C06 工具故障 | 一次性和持续故障均有 observation，恢复或明确失败/未完成 |

输入及检查点见 [cases.json](../examples/cases.json)。原始未指明员工类型的“在家上班”问题若影响适用规则，应先澄清；不为了命中 D03 擅自补成正式员工。

## 工程完成标准

离线测试、C01—C06 回放、正式 T01—T06 变异测试入口、保存行为及五份文档必须交付。Live 还必须完成六场景、语料变异和至少两条 observation 后不同合理动作的真实对照。缺凭证时这些项目保持未验证，整体 Live 验收未完成。

本轮修复补充：period/scope/conditions/reference_event先做安全规范化，用户有依据的硬约束与模型可修订解释分开记录；字段级错误允许合法恢复，不增加默认预算。C06B必须真实观察故障，动态对照不能使用未执行调用或同批并行动作来证明观察后的决策。当前实测离线142项、Live14项通过，旧失败记录完整保留，具体证据见03-evaluation.md。

不建设 Web、服务部署、权限系统、向量数据库、多 Agent 或生产级运行时。GitHub 创建、提交、推送和 SHA 核验是后续正式交付任务。
